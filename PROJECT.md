# ultracraft (майн+) — заметки по проекту

Документ для человека и для агента: что здесь есть, **почему** сделано именно так и что
делать дальше. Перечитывать перед крупными изменениями — часть решений неочевидна и
легко «улучшается» обратно в проблему.

## Что это

Клиент Minecraft: Java Edition, написанный с нуля на Kotlin/JVM: свой протокол, свой мир,
свой рендер. Официальные функции, доступ к мультиплееру, **без поддержки модов**.

Целевая версия зафиксирована: **26.3, протокол 777**. Не «последняя», а именно эта:
номер протокола и ID пакетов меняются каждый релиз, и привязка к «последней» превращает
любой апдейт в переписывание.

Замысел шире «поиграть»: это способ пройти путь игры целиком — от байтов в сокете до
пикселя на экране — и получить работающий клиент, а не мод к чужому. Отсюда требования,
которые не видны в игре: протокол отдельно от мира, мир отдельно от рендера, всё
тестируемое без окна и без видеокарты.

Проект не связан с Mojang и Microsoft. Код игры и её ассеты не распространяются: текстуры
читаются из установки игрока во время работы.

## Запуск и проверка

```powershell
.\gradlew.bat build                        # компиляция + 90 тестов — минимум перед «готово»
.\gradlew.bat :app:packageExe              # dist\ultracraft\ultracraft.exe (свой рантайм Java)
.\gradlew.bat :app:run --args="window"     # запуск из исходников
```

Команды клиента:

```
ultracraft.exe                окно: WASD, пробел, F — полёт, 1–9 — слот, ЛКМ/ПКМ — блоки, Esc
ultracraft.exe world          карта мира текстом (--at x,y,z — что лежит на сервере)
ultracraft.exe view           карта мира в PNG (CPU-рендер)
ultracraft.exe watch          что двигалось в мире за N секунд (проверка «нас видно»)
ultracraft.exe ping <сервер>  список игроков
ultracraft.exe join           проверка входа без окна
ultracraft.exe login          вход через Microsoft (одобрен Mojang 19.11.2026)
ultracraft.exe hotbar         что лежит в слотах и что в руке (--slot N — переключить)
ultracraft.exe hud            здоровье, броня, опыт, полосы босса и эффекты — числа для HUD
ultracraft.exe click          клик по слотам: --slots 36,1,0,37 (переложить, скрафтить)
ultracraft.exe textures <блок>  какие текстуры игра ставит блоку (проверка моделей)
ultracraft.exe mine           сломать блок и показать вердикт сервера
ultracraft.exe place          поставить блок из руки и показать, что вышло
```

Предметы в выживании взять негде, поэтому для проверок они выдаются командами через RCON:

```powershell
.\tools\rcon.ps1 "give Bank minecraft:stone 8"
```

На сервере для этого должны быть `enable-rcon=true` и пароль в `server.properties`.

Локальный сервер (оракул протокола): `.\tools\server-start.ps1`. Нужен **JDK 25** —
сервер 26.3 на 21 не стартует; `white-list` у него включён по умолчанию, скрипт это правит.
Отладка ломания: `.\tools\server-start.ps1 -Restart -DebugBlocks` — в лог пойдут строки
`Server ACK …` с вердиктом сервера по каждому пакету действия.

**Проверка без рук.** У окна есть `--demo`: ломает и ставит блок, печатает координаты, идёт
вперёд первые пару секунд — в логе видно тики, позицию и число отправленных пакетов.
`--frames N --hidden --out файл.png` рисует N кадров и сохраняет снимок — так проверяется
рендер без участия человека. Присутствие в мире для других проверяется вторым клиентом:
`watch --seconds 20` показывает сущности, которые двигались, вместе с их UUID.

## Архитектура: байты → мир → кадр

```
Socket → FrameCodec → Packet → MinecraftClient (вход, реконфигурация)
                                     ↓
                         Session (состояние play, keep-alive)
                        ↙                    ↘
      поток сети: чанки, сущности        главный поток: физика, ввод, GL
             ↓                                    ↓
      World.addChunk (потокобезопасно)      MeshPipeline (15 потоков)
             ↓                                    ↓
      очередь мешей ──────────────────→ загрузка в видеопамять (≤16 за кадр)
```

| Модуль | Роль | Зависимости |
|---|---|---|
| `protocol` | VarInt, строки, NBT, палитры, фрейминг, zlib | нет |
| `net` | соединение, вход, реестры, мир, сущности, пакеты действий | `protocol` |
| `auth` | Microsoft → Xbox Live → Minecraft services, сессии | нет |
| `app` | CLI, физика, меши, OpenGL, exe | `net`, `auth` |

Правило: `protocol` не знает про мир, мир не знает про рендер.

## Решения, которые нельзя менять молча

**Версия и ID пакетов — в одном месте.** `Protocol777` — единственный файл с числовыми ID.
Они меняются между релизами; разбрасывать их по коду значит гарантировать тихую поломку
при апдейте.

**Реестр блоков больше не приходит по сети.** С 26.x `minecraft:block` — встроенный реестр.
Клиент обязан знать таблицу состояний сам, поэтому `data/blocks-777.tsv` генерируется из
официального дата-генератора (`tools/build-block-table.js`) и в git не попадает.
Попытка взять имена блоков из `Registry Data` — тупик: пакета с блоками просто нет.

**Сетевой NBT без имени корневого тега.** С 1.20.2 корневой compound идёт как
`[type][payload]`. Чтение лишних двух байт сдвигает весь поток; именно на этом сначала
разъехались реестры.

**У чанка нет поля «количество секций».** Число секций = `height / 16` из реестра
`dimension_type`. В секции есть `fluid count` (с 1.21.5), а длина массива палитры больше
не передаётся — считается из bits per entry. После секций в буфере обязан остаться ноль
байт: это дешёвая проверка, что формат не поехал.

**Меш на чанк, а не на мир.** Раньше весь мир был одним буфером: правка блока требовала
пересборки 250 тысяч граней — секунда зависания на каждый клик. Теперь правка пересобирает
один чанк, а загрузка в видеопамять идёт пачками (≤16 за кадр), чтобы не превратить
исправление рывка в новый рывок.

**Кадр не строит геометрию.** Сборка меша — обход 98 304 блоков на чанк; в кадре это
десятки миллисекунд. Работа вынесена в пул `mcplus-mesh`, кадр только загружает готовое.
Ускорение при этом около 3×, а не 15×: упор в аллокации и память, а не в ядра. Дальше
поможет не «ещё потоков», а меньше allocations.

**GL — только в главном потоке.** Контекст привязан к потоку; рабочие потоки считают
FloatArray, но ничего не загружают. Нарушение этого правила — падение драйвера, а не
исключение в логах.

**Мир потокобезопасен, но слабо.** `chunks` — `ConcurrentHashMap`, `setBlock` под
`@Synchronized`, чтение блоков без блокировок. Запись `int` в массив атомарна; рабочий
поток может увидеть устаревшее значение, и это допустимо: в худшем случае одна грань
появится на кадр позже.

**Текстуры — из установки игрока.** Читаются из `versions/<id>/<id>.jar` при запуске
(1301 слой), ничего не копируется в проект. Сначала я читал `assets/indexes/34.json` —
это старый индекс, там только иконки и панорамы; текстуры блоков современный Minecraft
держит в jar версии.

**Тонирование — при загрузке в видеопамять, а не при чтении.** Трава и листва в файлах
серые: цвет им даёт биом. Умножение в момент чтения до текстуры не доходило (картинка
оставалась серой); перенос в `GlTextures.uploadBuffer` решил вопрос.

**Мипмапы выключены, фильтр `NEAREST`.** Грань блока занимает 3–4 пикселя: производная UV
большая, сэмплер уходит на нижний уровень мипмапа, и мир становится серо-белым. Пиксельная
фактура — это уровень 0.

**UV считаются по грани.** Один общий набор UV поворачивал бока блоков. Сейчас: верх и низ
`u = x, v = 1 − z`; бока по X `u = z, v = 1 − y`; по Z `u = x, v = 1 − y`. `v = 1 − y`
нужен потому, что текстура грузится сверху вниз.

**Сервер выкинул — игрок должен это увидеть.** Консоль у упакованного exe своя, и Windows
закрывает её вместе с процессом: и падение, и кик выглядели как «игра просто исчезла».
Теперь любое аномальное завершение пишется в `ultracraft-error.txt` и показывается окном
(`CrashReport`), а `Session.send` никогда не бросает исключение в игровой цикл: он
запоминает причину в `closeReason`, игровой цикл по ней выходит, окно закрывается штатно.

**Полёт — только с разрешения сервера.** `Player Abilities` (clientbound 0x41) сообщает бит
«можно летать». Без него выживание кикает через ~80 тиков с `Flying is not enabled`; клиент
поэтому игнорирует F и говорит, что сервер не разрешает.

**Камера считает углы в другую сторону, чем протокол.** На провод уходит `-yaw, -pitch`:
иначе сервер выбирает `pick()`-ом другой блок и любое действие по блоку для него бессмысленно.

**Грани на границе незагруженного чанка рисуются.** Раньше сосед из ещё не приехавшего
чанка считался стеной, и у каждого пришедшего чанка пропадала полоса граней по периметру:
чанки мешатся по мере прихода, соседей в этот момент обычно нет. Вода вдали и поверхность
издалека выглядели как отдельные кубы в пустоте. Теперь «чанка нет» = «воздух»: двойные
совпадающие грани внутри мира не видны, а дыра в мир — видна.

**Мёртвый игрок не получает чанков.** Если игрок умер в прошлой сессии, сервер держит его
мёртвым и не стримит ему мир вообще: клиент видит «ни одного чанка». Лечится запросом
`Client Status: perform respawn` (0x0C, действие 0), который для живого игрока сервер
игнорирует; `WorldCollector` шлёт его сам, если за треть таймаута не пришло ни одного чанка.

**Физика: прижатие считается от пройденной точки.** Если прижимать от откатанной позиции,
стоящий ровно на высоте 63.0 персонаж каждый кадр «подпрыгивает» на целый блок. Проверка —
`--demo` или лог высоты: `y` должен стоять на месте.

**Мир идёт на 20 тиках, а не на кадрах.** Физика и отправка позиции вызываются только из
тика по 50 мс (не больше 5 тиков за кадр, остаток отбрасывается), а камера между тиками
интерполируется. Причина не в красоте: сервер принимает не больше одного пакета движения за
свой тик, а `Client Tick End` он вообще считает, чтобы понять, что клиент загрузился.

**Поток движения начинается с пустого `Client Tick End`.** Сервер требует разделитель
**до** нового пакета позиции, иначе кикает с `Invalid move player packet received`; первый
тик после входа всегда хочет что-то сказать (позиция спавна), поэтому разделитель уходит
вперёд, ещё до первого пакета.

**Позиция сервера — истина, а не догадка по рельефу.** Спавн берётся из `Synchronize
Position`, а не из «первый твёрдый блок сверху»: полблока разницы — и сервер правит каждое
движение. Телепорты сервера кладутся в очередь (`Session.pollTeleport`), игровой поток
забирает **последний**: цепочка старых исправлений протащила бы игрока через все прошлые
точки.

**Отправляется самый дешёвый пакет, описывающий изменение.** Движение и поворот — вместе
(`Set Player Position and Rotation`), только движение — `Set Player Position`, только
поворот — `Set Player Rotation`, сменилась опора под ногами — `Set Player Movement Flags`.
Раз в 20 тиков позиция отправляется заново, даже если игрок стоит: иначе сервер теряет
представление о том, где мы.

**Одобрение Mojang получено, и оно было единственной преградой.** Цепочка Microsoft → Xbox
Live → XSTS → `login_with_xbox` проходила и раньше, но последний шаг отвечал `403 Invalid app
registration`, пока id приложения не попал в allow list по заявке `aka.ms/mce-reviewappid`.
19.11.2026 заявку одобрили — **код не менялся**, `mcplus login` заработал как был.

**Сессию у Mojang надо подтверждать, и она капризна к частым входам.** После `Encryption
Request` клиент обязан сходить в `sessionserver.mojang.com/session/minecraft/join` **до**
отправки `Encryption Response`, иначе сервер кикает `multiplayer.disconnect.unverified_username`.
Проверено замерами: после паузы 65 секунд первый же вход проходит, а два входа подряд — нет:
сервер сессий несколько секунд не принимает новую сессию того же профиля. Поэтому вход
повторяется до трёх раз с паузой 5 секунд, а кик переводится в понятную фразу.

**Упаковка в exe имеет три ловушки.** Нативные библиотеки LWJGL должны попасть в
зависимости (`org.lwjgl:lwjgl:$version:natives-windows`, запись без версии молча
игнорируется); jpackage не смотрит внутрь jar, поэтому DLL распаковываются рядом с exe;
`ImageIO` в урезанном рантайме падает на создании кеш-файла — лечится `setUseCache(false)`.

**Старт: сначала окно, потом мир.** Ждать загрузку мира целиком — это 6 секунд пустого
экрана. Сейчас ждём 25 чанков вокруг спавна (≤1.5 с), открываем окно, остальное приезжает
в потоке-читателе: 441 чанк в сцене через ~0.5 с после открытия.

## Текущее состояние

Работает: вход на offline-сервер и на **сервер с проверкой аккаунтов** (`--online` после
`login`: шифрование AES/CFB8 и подтверждение сессии у Mojang), приём чанков и реестров,
полный воксельный мир,
рендер на видеокарте с текстурами из игры, ходьба/прыжок/полёт с коллизиями, **ломание
блоков в выживании по-настоящему** (сервер подтверждает: `world --at` → `air`, включая камень
за 7.5 с) с трещинами и подсветкой цели, **инвентарь и хотбар**: сервер присылает содержимое
слотов, 1–9 переключают слот, правый клик ставит блок из руки (проверено: `stone` на сервере,
счёт уменьшился),
**HUD поверх сцены**: прицел, хотбар с количеством, здоровье, голод, полоса и уровень опыта,
название предмета при смене слота, **полоса босса** (wither и `/bossbar`: имя, доля, цвет,
насечки), **иконки эффектов** (полезные в ряд, остальные столбцом, фон «фоновых» эффектов),
**броня** (очки из таблицы предметов, ряд значков над сердцами),
**экран смерти и возрождение** (сервер присылает
`Set Health`/`Set Experience`, смерть — здоровье 0),
**чат**: приём системных сообщений и сообщений игроков, отправка сообщений и команд
(T — сообщение, `/` — команда, стрелки — история), строки гаснут через 10 секунд,
**свет из чанка**: небо и блоки по четыре бита, день и ночь по `Set Time`, цвет неба,
туман и яркость от времени суток, дождь гасит свет, **солнце, луна с фазами, звёзды и
облака** из текстур игры, своё небо у ада и энда, **текстуры блоков из моделей** — у
ступеней, плит, заборов и ещё шестисот блоков больше нет клетчатой заглушки,
**формы блоков**: плиты, ступени (включая угловые), заборы, стены, двери и люки, ковры,
снежные слои, факелы и растения крестом — настоящими коробками и плоскостями, а не кубами
(файл состояний несёт свойства `type`, `facing`, `half`, `layers`…),
**цвета биомов**: трава, листва и вода красятся оттенком своего биома (67 биомов из данных
игры, номер биома приходит в секции чанка),
**вода и лёд полупрозрачные** — отдельный проход с сортировкой по дальности, сквозь воду
видно дно; стекло и листва вырезаются по альфе,
**иконки предметов** из `textures/item` (у блоков — текстура модели, у остальных предметов —
свой файл), **предмет в руке** — иконка в правом нижнем углу,
**контейнеры**: `Open Screen` и `Container Set Content` для любого окна, сетка сундука,
верстака и печи, клик по слоту с настоящим номером окна, правый и shift-клик,
перетаскивание (начало, проход, конец) и `Close Screen`,
**мобы**: корова, свинья, овца, курица, крипер и паук — коробками в ванильных пропорциях
с **настоящими текстурами** (развёртка каждой коробки из ванильной модели); зомби, скелет,
эндермен и пиглин — моделью человека со своей текстурой; ноги качаются по пройденному пути,
рамки с предметами внутри рисуются иконкой,
**частицы**: `Level Particles` (0x30) с новым форматом 26.x (тип частицы идёт первым,
смещения клиент разбрасывает сам), спрайты из `textures/particle` в одном атласе: огонь,
дым, искры, брызги и взрывы с покадровой анимацией,
**экран контейнера**: заголовок и рамки слотов; в инвентаре работают правый и shift-клик,
при уроне экран краснеет на 0,4 секунды,
**предметы в мире**: выпавшие блоки — вращающимися мини-кубами настоящих текстур, сферы
опыта — жёлтыми кубами, из сломанного блока сыплются кусочки; блок в руке — объёмным кубом
с наклоном и взмахом,
**звук**: OpenAL и `stb_vorbis`, 1984 события из `sounds.json`, шаги по блоку под ногами,
ломание и установка блоков, боль и смерть игрока, сундук, повышение уровня, дождь и удары
кирки; фоновая музыка из 32 треков `music.game` включается клавишей M и запоминается,
**мир**: туман биома (болото, тёмный лес) поверх цвета времени суток,
**выживание**: удар по мобу (`attack` 0x01 с номером сущности, хитбоксы по типу),
выброс предмета по Q и всей стопки по Ctrl+Q, имена мобов из метаданных над головой,
биом в отладочной строке, экран смерти по-русски,
**бой и мелочи**: красная вспышка на модели при уроне (`entity_event` 0x22), стрелы и
снаряды видны иконками, рамка чанка по F3+G, в F3 время суток и погода,
**интерфейс и мир**: меню паузы по Escape («Продолжить», «Выйти», обзор, громкость,

## Наполнение: новая мерка

С этого момента цель — не «что мешает играть», а **паритет по контенту**: игрок на обычном
сервере 26.3 должен видеть то же, что в оригинале. Правила и полная опись — в
[docs/CONTENT.md](docs/CONTENT.md) (оригинал против нас, план по этапам) и
[docs/content-appendix.md](docs/content-appendix.md) (полные списки из данных игры).

Три следствия, которые нельзя забывать:

- **Мы клиент, а не игра.** Мир, мобы, редстоун и лут считает сервер — половина наполнения
  приходит по сети. Разрыв почти целиком в показе и взаимодействии, а не в симуляции.
  Редстоун у нас уже «работает»; не работает то, что рычаг нарисован кубом и щелчка не слышно.
- **Контент, а не оптимизация.** Внутренние решения оригинала (палитровые контейнеры,
  световой движок, запекание моделей) не копируем — список и замены в `CONTENT.md`, часть 4.
- **Совместимость — рамка, а не цель.** Ни один этап не принимается, если клиент перестал
  заходить на ванильный сервер с `online-mode=true`.

## Долги и ограничения

- **Игрок — модель с анимацией ходьбы, но без тонкостей.** Скин
  `entity/player/wide/steve.png` (64×64, шесть частей тела), поворот из
  `entity_position_sync`/`entity_look`, руки и ноги качаются по измеренной скорости и
  пройденному пути. Нет: тонкой модели (слим-скины выглядят как обычные), чужих скинов
  (все выглядят Стивом), поворота головы отдельно от тела, поз сидения и плавания.
- **Ломание работает по-настоящему, для всех блоков.** Причина прошлых неудач была не в
  времени, а в коде действия: в 26.x `Player Action` нумеруется в порядке enum сервера, где
  `CHANGE_DESTROY_DIRECTION` стоит между `START` и `ABORT`, поэтому «остановить» — это `3`, а
  старое `2` сервер понимает как «отменить». Мгновенные блоки (трава, цветы) ломались, потому
  что уничтожаются на `START`, — из-за этого ошибка и пряталась. Проверено на сервере: песок
  `-58,62,40`, земля `-58,61,40`, **камень `-58,60,40` (7.5 с рукой)** — все `air` по
  `world --at`; в логе сервера `Server ACK … true destroyed`.
- **Клиент держит кнопку, пока блок не исчезнет**, а не отпускает по своей оценке: сервер
  считает прогресс сам и ломает блок на 1.0, а `STOP` лишь просит доделать (принимается с 0.7).
  Оценка из `BreakProgress` нужна только для трещин и для момента, когда попросить «доделай».
- **`mine` в CLI копает блок рядом, а не под ногами.** У CLI нет физики: выкопав опору, игрок
  остаётся в воздухе, и сервер через несколько секунд кикает за `floating too long` — на этом
  сломался первый замер камня.
- **Инвентарь можно двигать: клик по слоту, экран на E, крафт 2×2.** Пакет `Container Click`
  применяется сервером сам, а «предсказания» в нём — хеши предметов, которые нужны лишь
  чтобы сервер не слал лишних обновлений. Мы шлём пустые предсказания и **заведомо неверный
  `stateId`**: тогда сервер отвечает полным состоянием меню (слоты + курсор), и клиенту не
  нужно ни считать хеши, ни повторять логику меню. Цена — один лишний пакет на клик.
  Проверено: `click --slots 36,1,0,37` берёт брёвна, кладёт в сетку, забирает результат
  (4 доски) и убирает в хотбар; в логе видно `результат крафта (0): oak_planks × 4`, счёт
  бревна уменьшается. В окне: E открывает экран (41 слот — без брони и оффхенда), клик
  перекладывает, самотест демо кликает слот 36 и сетку и печатает «сетка крафта oak_log,
  результат oak_planks».
- **Курсор приходит не слотом, а отдельным пакетом** `set_cursor_item` (0x62), а в
  `container_set_content` он идёт **последним полем после 46 слотов**. Первая версия не читала
  ни то, ни другое и показывала пустой курсор, хотя предмет уже был в руке.
- **Предметы с компонентами не разбираются.** Стек на проводе — это `count, item id, patch`,
  где у каждого компонента свой кодек и своя длина. Пустой patch (обычная стопка блоков)
  читается точно; при непустом известно только количество, и предмет показывается как «?».
  Поэтому же `Container Set Content` с таким стеком отбрасывается целиком (пакет
  length-delimited, десинка не будет).
- **Слоты адресуются двумя разными способами.** `Container Set Content/Slot` — это слоты
  *меню* игрока (хотбар 36..44), а `Set Player Inventory` — слоты самого инвентаря (хотбар 0..8).
  Спутать легко и незаметно: предметы приезжают, но «в руке» пусто. Проверено тестами.
- **HUD уже поверх сцены, а инвентарь — ещё в мире.** Хотбар, сердца, еда и полоса опыта
  рисуются отдельным проходом с ортопроекцией; панель инвентаря по-прежнему висит в 1.2 блока
  перед камерой.
- **Полоса босса показывает не всё, что умеет.** Имя, доля, цвет и насечки рисуются, но флаги
  «затемнять экран», «играть музыку» и «туман мира» только разбираются: затемнения и музыки
  нет. Доля меняется скачком, без ванильного сглаживания (`LerpingBossEvent`), потому что
  сервер и так присылает обновления часто; на редких событиях это заметно.
- **Иконки эффектов без чисел.** В 26.3 ванильный HUD больше не пишет длительность под
  иконкой — только сами иконки (это проверено по `Hud.extractEffects`, там нет текста).
  Поэтому и у нас нет ни секунд, ни названий на экране; числа печатает `hud`.
  Мигание иконки за 10 секунд до конца (`MobEffectInstance.endsWithin(200)`) не сделано.
  Иконки грузятся только для эффектов из `data/effects-777.tsv`: без таблицы рисуется
  серая заглушка, потому что id эффекта по сети приходит числом.
- **Прочность видна у предмета в руке.** Урон читается из компонента `damage` (таблица
  `data/components-777.tsv`), максимум — из `item-stats`; под выбранным слотом рисуется
  полоска. На значках в инвентаре и контейнере полосок пока нет, и другие компоненты
  (`custom_name`, `enchantments`) по-прежнему делают стек «неизвестным». Броня без прочности,
  воздух не показывается: в ванили он считается клиентом сам, отдельного пакета нет.
- **Кириллица рисуется системным шрифтом.** К ASCII-странице дорисовывается вторая,
  сгенерированная AWT (Dialog, без сглаживания): буквы читаются, но отличаются от
  ванильного пиксельного шрифта, а редкие глифы вне U+0400…U+047F отсутствуют.
- **Чат уходит без подписи профиля.** В `Chat` нет подписи, а подтверждение полученных
  сообщений пустое: оффлайн-серверы такое принимают (в логе видно `[Not Secure] <mcplus> …`),
  online-серверы с обязательной подписью — нет, пока не сделаны чат-сессии (этап 7).
  Команды работают всегда: `Chat Command` — это просто строка.
- **В чате нет прокрутки, копирования и автодополнения.** Видно 10 последних строк,
  стрелки листают отправленные строки; кириллица теперь рисуется.
- **Экран инвентаря — в мире**: панель в 1.2 блока перед камерой, попадание мыши считается
  той же геометрией (тест проверяет круговой пересчёт для всех 41 слота). Броня и оффхенд в
  меню есть, но не рисуются — им пока нечего делать. Переедет на экран вместе с этапом 4.
- **В окне только обычный левый клик.** Правый клик (взять половину) и shift-клик (быстро
  переложить) есть только у консольной команды: `click --button 1` и `click --quick`.
- **Хеши предметов не считаются.** Поэтому клик всегда несёт пустые предсказания и неверный
  `stateId`, а сервер отвечает полным меню. Работает, но это лишний пакет на каждый клик.
- **Выгрузка чанков грубая.** Дальние чанки (радиус + 4) выбрасываются из памяти раз в
  секунду, без учёта того, что игрок вот-вот вернётся: при беге туда-обратно они качаются
  заново. Сохранения изменённых блоков на диск нет — это дело сервера.
- **Список по Tab и F3 — минимум.** В табло только имена игроков: нет ping, голов и
  сортировки по команде; в отладке нет биома, памяти и профессии.
- **Мобы — шесть моделей с текстурами, остальные упрощены.** Корова, свинья, овца, курица,
  крипер и паук натягивают настоящую шкуру, но пропорции коробок упрощены. Эндермен, пиглин
  и зомби-пиглин рисуются моделью человека с их текстурой, а не своей геометрией; рамки с
  предметами показывают только иконку, без самой рамки и поворота. Остальные типы — коробки.
- **Бой — только вспышка.** Урон рисуется красной подсветкой модели на 0,3 с; анимации
  замаха мобов, смерти и отбрасывания нет. Стрелы, снежки и жемчуг — плоские иконки без
  поворота по полёту. Рамка чанка рисуется только вокруг текущего чанка и только по F3+G.
- **Музыка — один трек в памяти.** Трек декодируется целиком (десятки мегабайт), играет,
  затем две минуты тишины. Нет музыки в меню, творческом режиме и Нижнем мире, нет
  потокового воспроизведения.
- **Туман биома — только цвет.** `effects.fog_color` подменяет цвет тумана, но не его
  плотность; в Нижнем мире и Энде свои правила не сделаны.
- **Третье лицо без столкновений камеры.** F5 отъезжает на 4 блока и не проверяет стены:
  камера может оказаться внутри блока. Своя модель рисуется скином по умолчанию, без брони
  и предмета в руке.
- **Дальность прорисовки — это выгрузка.** Настройка меняет расстояние, дальше которого
  чанки выбрасываются из памяти; сервер всё равно стримит их все, поэтому память и трафик
  растут до выгрузки. Полноценного «не просить далёкие чанки» нет.
- **F2 и F11 — минимум.** Снимок сохраняется в `screenshots/` с датой в имени; полный экран
  переключается, но его выбор теперь сохраняется в настройках.
- **Под водой только вид и туман.** Плавать нельзя: вода не держит игрока, нет всплытия,
  пузырей и звука погружения; синий слой — картинка поверх кадра.
- **Настройки — только обзор и громкость.** В паузе стрелками меняются FOV (40–110°) и
  общая громкость; дальности прорисовки, чувствительности и языка в меню нет.
- **Пауза не останавливает сервер.** Escape открывает меню и перестаёт слать движение, но
  мир продолжает жить: одиночной игры с локальным сервером нет.
- **Табло — только боковая панель.** Цели, очки и заголовок читаются; списка игроков,
  командных цветов, форматирования чисел и позиции «под ником» нет.
- **Снег — только картинка.** В холодном биоме во время дождя летят снежинки; настоящего
  снегопада, накопления слоёв и звука дождя нет.
- **Удар — это только пакет.** Клиент шлёт `attack` и взмах, урон и отбрасывание считает
  сервер; перезарядки удара, критических попаданий и анимации замаха у мобов нет. Хитбоксы
  упрощены: коробка по типу моба, без отдельных частей.
- **Выброс предмета без предсказания.** Q шлёт `player_action` с `DROP_ITEM`/`DROP_ALL_ITEMS`,
  но клиент не рисует вылетающий предмет до ответа сервера.
- **Подсказки и счётчики — только в инвентаре и контейнере.** Подсказка не показывает
  прочность числом и не переносится по строкам; в мире над предметами ничего не рисуется.
- **Экран контейнера — панель в мире.** Заголовок и рамки слотов есть, но фона, кнопок и
  ванильных текстур окна нет; остальные 20 меню показываются общей сеткой.
- **Контейнеры — клики и прогресс.** Левый клик, правый (половина), shift+левый
  (быстро) и перетаскивание работают и в окне, и в `container --click/--drag`; у печи
  нарисованы пламя и стрелка по `Container Set Data`, но грубо (цветные полоски, а не
  спрайты).
- **Частицы — спрайты, но не все типы.** Картинки берутся из `textures/particle` и
  собираются в атлас; у кого своей картинки нет, рисуется `generic_0`. Цвет пыли не
  используется, предметные и вибрационные частицы пропускаются, физика частиц упрощена.
- **Звук есть, но не весь.** Шаги, ломание, установка, боль и смерть играются на OpenAL из
  настоящих `.ogg`; музыки, звуков мобов, окружения и сундуков нет. Громкости и субтитров
  нет; звук берётся из **скачанных лаунчером** ресурсов (`assets/objects`), а без них клиент
  молча выключается. Незнакомый блок звучит камнем.
- **Предметы в мире — блоки кубом, остальное иконкой.** Выпавший блок вращается мини-кубом,
  инструмент и еда — плоской иконкой к камере; стопки с добавленными компонентами
  (`minecraft:damage` и другие) не разбираются и не видны, покачивания, тени и подсветки
  нет.
  У выпавших предметов нет покачивания, тени и подсветки, у сфер опыта — настоящей текстуры
  (жёлтый куб из текстуры золота). Кусочки сломанного блока летят без столкновений и живут
  полсекунды; это украшение, а не физика.
- **Иконки предметов неполные.** Текстура берётся по имени предмета из `textures/item`;
  у зелий, стрел с эффектом и других предметов с наложениями (overlay) будет видна только
  основа. У блоков иконка — грань их модели, поэтому у ступеней это доски.
- **Атлас упёрся в предел видеокарты.** Слоёв 2027 при типичном пределе 2048: текстуры
  предметов, совпадающие с блоками, не грузятся. Дальше расширять массив некуда — понадобится
  отдельная текстура для предметов.
- **Формы блоков — десять семейств, остальное кубами.** Плиты, прямые и угловые ступени,
  заборы, стены, двери, люки, ковры, снежные слои, факелы и растения крестом рисуются
  правильной геометрией. У открытых дверей и люков петля не учитывается — панель всегда
  поворачивается в одну сторону; посевы (пшеница, морковь, картофель) не рисуются вовсе —
  их текстуры по стадиям, а не по имени. Растения крестом во всю клетку, без ванильных
  отступов и наклона.
- **Цвета биомов приблизительные.** Трава красится только сверху: у бока травяного блока
  свой запечённый оттенок, отдельного слоя-наложения нет. Цветовые карты сэмплируются
  ближайшим пикселем без треугольной интерполяции ванили; туман и цвет неба от биома не
  зависят. Модификаторы болота и тёмного леса сведены к постоянным цветам, а не к шуму.
- **Прозрачность — только у воды и льда.** Их грани идут в отдельный буфер, смешиваются и
  не пишут в глубину; чанки рисуются от дальних к ближним. Стекло и листва непрозрачны по
  альфе (вырезание), но не смешиваются: полупрозрачных стёкол и цветной воды с альфой нет.
  Подводного тумана и цвета тоже нет.
- **Снег и звук дождя не сделаны.** Снежных слоёв нет, звука в клиенте нет вовсе.
- **Свет сглажен по углам.** Каждый угол грани усредняет свет четырёх клеток вокруг себя;
  непрозрачные соседи не затемняют стык. Тени не считаются.
- **Небо приблизительное.** Солнце и луна ходят по плоскости восток-запад без наклона,
  облака — один слой на высоте 192 без объёма и без дождливой текстуры; звёзды —
  процедурные точки, а не ванильная сфера.
- **`Light Update` пока не приходил в тестах.** Установка факела через RCON меняла блок
  (`Block Update` приходил), но пакетов света сервер не присылал — разбираться отдельно;
  после установки блоков свет обновится при перезагрузке чанка.
- **CPU-рендер (`view`) и GPU-рендер (`window`) — два разных кода.** Меши общие, шейдеры
  разные; CPU-путь оставлен как запасной и для скриншотов без дисплея.

## Ближайшие шаги

Порядок задан не технологиями, а тем, сколько контента этап открывает
([docs/CONTENT.md](docs/CONTENT.md), часть 3). Первые три:

1. **Этап 2 — остатки**: снег (слои) и звук дождя (звука в клиенте пока нет вовсе).
   Свет, сглаживание, день и ночь, погода, светила, облака и цвета биомов уже сделаны.
2. **Этап 1 — остатки**: прочность предмета (нужны компоненты стека), воздух, пауза.
3. **Этап 3 — формы дальше**: угловые ступени и петли дверей, посевы по стадиям.
   Текстуры моделей, десять семейств форм, прозрачность, иконки предметов и предмет в руке
   уже сделаны.
4. **Этап 4 — контейнеры дальше**: перетаскивание, остальные 20 меню, заголовки и фон.
   Сундук, верстак, печь, правый и shift-клик уже работают.
5. **Этап 5 — мобы дальше**: зомби, скелет и остальные 155 типов, `Set Entity Data`,
   текстуры на моделях, предметы на земле и опыт. Шесть животных уже рисуются моделями.

Дальше по плану: выживание (этап 6), чат и мета (этап 7), звук и частицы (этап 8), оболочка
игры (этап 9).

Технические долги, не привязанные к контенту: выгрузка далёких чанков (память растёт),
шаговые пути в `entity_position_sync` (`path type = 1`), `move_entity_pos_rot` (0x37).

  падал на `Invalid boolean byte: 10`; а время в 26.x приходит картой часов мира

  присылал даже при установке факела через RCON — записано в долги.

- **2026-11-19.** Текстуры блоков из моделей. До этого текстура угадывалась по имени блока
  (`oak_stairs_side`, `oak_stairs`…), и у **600 блоков из 1286** — ступеней, плит, заборов,
  дверей, факелов — такого файла нет: они рисовались клетчатой заглушкой `missing`.
  Теперь читается настоящая цепочка игры: `blockstates/<блок>.json` → `models/<модель>.json`
  → `parent` (текстуры наследуются, дочерние перекрывают) → грани `up/down/north` из
  `elements`, ссылки `#all` разворачиваются по таблице текстур. Две ловушки: у блока бывает
  `multipart` (берём первую часть), а значение текстуры в 26.x бывает не строкой, а объектом
  `{"sprite": "block/glass", "force_translucent": true}` — без этой ветки стекло и ещё
  40 блоков оставались без модели. Итог: 1282 блока из 1288 получают верх, низ и бок из
  модели за ~130 мс при запуске; проверка — команда `textures` (`oak_stairs` → `oak_planks`,
  `grass_block` → `grass_block_top`/`dirt`/`grass_block_side`) и значки в хотбаре
  (`shapes-textures.png`). Геометрия при этом по-прежнему кубическая — это следующий шаг.
  Отдельная грабля: Kotlin поддерживает **вложенные** блочные комментарии, и запись
  `blockstates/*.json` внутри KDoc открыла второй комментарий — компилятор «потерял»
  половину файла и говорил «unresolved reference» на функции, которые никуда не делись.

- **2026-11-19.** Формы блоков: плиты, ступени, заборы, двери. Номер состояния сам по себе
  не говорит, плита это или куб, — свойства лежат в данных игры, поэтому третья колонка
  таблицы блоков теперь несёт `type=bottom`, `facing=north`, `half=top`… (35 723 состояния,
  файл вырос с 0.8 до 2 МБ, в git не попадает). Мешер перестал быть «куб на блок»: форма —
  это набор коробок, куб — одна коробка от 0 до 1, поэтому свет, UV и отсечение граней
  считаются одним кодом. Правило отсечения изменилось: частичный сосед **не** скрывает
  грань (за плитой видно половину стены), а совпадающие боковые грани двух одинаковых плит
  скрываются, иначе они мерцали бы. Проверено тестами: низ плиты 48.0–48.5, верх 48.5–49.0,
  ступенька только на стороне `facing`, дверь тоньше 3/16, забор без связей — столб 4/16,
  две плиты рядом дают 10 граней вместо 12, а камень рядом с плитой сохраняет все шесть.
  На снимке `shapes.png` видны ступенька, полублок, столб с перекладинами и тонкая дверь.

## Как поддерживать эту память

- Обновлять после каждого этапа, а не «когда-нибудь»: цифры и ограничения устаревают
  быстрее кода.
- Записывать **почему**, особенно если решение выглядит странным: именно его захочется
  «улучшить» обратно.
- Числа брать из реальных запусков, а не из головы. Оценки в днях не писать — они уже
  подводили (см. «Честно про оценки» в `docs/START-HERE.md`).
- Ограничения перечислять честно: список долгов — это карта, а не признание.

## Стиль кода

- Kotlin, JVM 21, без фреймворков; исключения — `ProtocolException`/`AuthException`.
- Комментарии и пользовательские строки — по-русски; идентификаторы — по-английски.
- Числовые ID пакетов — только в `Protocol777`.
- Никаких синглтонов и глобального состояния: зависимости через конструктор.
- Всё, кроме `app/gl`, обязано работать без окна и иметь тесты.
- В `app/gl` GL-вызовы только в главном потоке.
