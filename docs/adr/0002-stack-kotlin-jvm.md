# ADR-0002: стек — Kotlin 2.1 на JDK 21 LTS

- Статус: принято
- Дата: 2026-11-18

## Контекст

Нужен язык и рантайм для совместимого клиента: сеть, мир, игровая логика, позже рендер.
Разработчик один, машина — Windows-ноутбук (Intel Core Ultra 7 255H, Intel Graphics, 24 ГБ RAM).

## Решение

- Язык: **Kotlin 2.1**, JVM target **21 LTS** (Temurin 21.0.13).
- Сборка: **Gradle 8.10.2** через wrapper.
- Модули: `protocol` (байты, без зависимостей), `net` (соединение, ping/login),
  `app` (CLI), позже `world`, `game`, `render`.
- Сеть: `java.net` + собственный фрейминг на старте, Netty — когда появится реальная
  нагрузка и несколько соединений.
- JSON: `kotlinx.serialization`. Рендер (позже): LWJGL 3, OpenGL 4.6.

## Обоснование

- Знание протокола живёт в Java-мире: документация, Minestom как референс, сам эталон на JVM.
- Один язык на всё, включая рендер (LWJGL — биндинги для JVM).
- Скорость итерации важнее пиковой производительности: 20 TPS JVM держит с запасом,
  профилирование — JFR.
- OpenGL 4.6 достаточно для воксельного рендера на Intel Graphics.

## Следствия

- Нужен JDK 21 у каждого, кто собирает проект; версия зафиксирована toolchain-ом.
- Kotlin-плагин версии 2.1.0 требует Gradle 8.x — обновление Gradle делать осознанно.
- При переходе на Netty меняется только `net`, `protocol` не затрагивается.

## Отвергнутые варианты

- **Rust** — современнее и быстрее, есть Valence/Pumpkin, но протокол выводится заново
  и итерации по геймплею медленнее.
- **C#** — нет готовой экосистемы под MC-протокол.
- **TypeScript** — оставлен для тулинга (дамп пакетов, скрипты), не для игры.
